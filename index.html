Data Flow

One pipeline, ingest to recommendation

Every conjunction on the dashboard passes through the same seven stages — deterministic, reproducible, and fully audited at each step.

01
Ingest
celestrakService pulls 3LE TLE sets from CelesTrak's public GP API.
02
Filter & Seed
seedService keeps LEO objects (perigee < 2000km), caps at 500, persists to MongoDB.
03
Propagate
propagationService runs SGP4/SDP4 to produce ECI/ECEF state vectors over time.
04
Detect
conjunctionService screens all objects within 100km and refines TCA via parabolic fit.
05
Estimate
riskService runs a 2-D B-plane Monte Carlo model to compute collision probability.
06
Optimize
maneuverService tests candidate Δv burns with a J2/RK4 integrator, picks the safest, smallest.
07
Visualize
CesiumGlobe renders before/after trajectories on a 3D globe for the operator.
CelesTrak API→ celestrakService→ seedService→ MongoDB→ Express REST API→ React Query→ CesiumGlobe

Core Services

celestrakService
Fetches and parses TLE sets from CelesTrak, inferring object type from naming convention.
seedService
Orchestrates the full ingest → filter → persist → scan → store pipeline end to end.
demoService
Synthesizes a physically consistent debris object guaranteed to pass ~0.7km from the ISS.
propagationService
SGP4/SDP4 wrapper: TLE parsing, ECI/ECEF propagation, trajectory sampling.
conjunctionService
Screens close approaches within 100km and refines TCA with parabolic three-point fitting.
riskService
2-D B-plane Gaussian Monte Carlo collision-probability model, seeded for reproducibility.
maneuverService
J2/RK4 numerical propagator plus candidate-burn generation and safety optimization.
jobQueue
Single-threaded, in-process queue that runs analysis and maneuver jobs without blocking HTTP.
auth middleware
Demo mode injects an OPERATOR user automatically; production mode parses bearer tokens.

Design Record

Eight decisions that shape the system

The choices that explain most of what the codebase looks like today.

01
In-memory MongoDB for a zero-setup demo — nothing to install, but data is lost on restart.
02
Async job queue keeps expensive analysis and maneuver-generation work off the HTTP thread.
03
Dual propagators — SGP4 for baseline orbit determination, J2/RK4 numerical integration for maneuver simulation.
04
Deterministic PRNG (mulberry32, seed 42) makes every Monte Carlo run reproducible.
05
Synthesized demo scenario guarantees a CRITICAL conjunction regardless of when the seed runs.
06
Configurable thresholds live on the backend — never hardcoded into the frontend.
07
Prototype disclaimers run throughout the UI and API responses, never hiding the model's maturity.
08
No real authentication in demo mode — an operator role is injected automatically so the flow is never blocked.
Analysis of a prototype system — not flight-certified, not for operational collision avoidance
